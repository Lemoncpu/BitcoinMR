# 当前分布式实现

每条业务键都包含平台，避免两个数据源相同编号混合。Mapper按实际输入切片产生，常规阶段以节点、用户对、用户月份等完整业务身份哈希分区，默认4个Reducer。

| 任务 | 实际工作流 |
| --- | --- |
| MR7 | 节点统计、归一化边、迭代传播、误差汇总、全局范围排序与分区偏移排名 |
| MR18 | 用户/日/目标计数、用户每日汇总、按用户日期二次排序的历史基线、待核查用户汇总 |
| MR22 | OTC过滤、UTC星期小时桶、Combiner求和、Reducer求和 |
| MR25 | SOURCE首次评分月、用户月事件数、带标记用户Join、群组偏移汇总 |
| MR26 | 规范用户对、反向边Join、评分差异、局部与全局Top10 |
| MR27 | 负边锚定SOURCE Join、B→C正边半连接、完整负边及不同中介汇总 |

业务Writable明确字段序列化次序。分区键与GroupingComparator一致；排序额外保留时间、来源kind或中介，保证基准状态先到。Join值保留来源标记，避免依赖Hadoop复用的Key对象。

Combiner仅用于可结合的计数、和、平方和、最值等状态；比例在完整汇总后计算。MR7用范围分区及分区前缀偏移得到全局排名；MR26局部TopK候选再全局合并，保留完整确定的排序规则。

MR7每轮读取上一轮状态，生成新目录；两个平台L1均小于0.01时停止，默认最多200轮。Job失败会阻止后续阶段与发布。PipelineAudit读取真实manifest，不代替业务计算。

MR7通过HdfsToHbase的Map-only流程导入；其余聚合结果可以逐分片流式写入HBase。写入确认完成后才切换current代次，页面固定读取该代次。原始CSV仅用于输入和独立验证，核心业务计算在Hadoop完成。

运行入口与路径见项目README，具体时序定义见TEMPORAL_JOBS.md及MR25_DEFINITION.md，路径冲突见RELATION_JOBS.md。
